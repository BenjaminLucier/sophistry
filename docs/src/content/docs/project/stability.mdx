This page describes how sophistry versions its API, which entry points you can rely on, and how the Solid binding tracks Solid 2 while Solid 2 is a release candidate.

## Versioning

sophistry follows [semantic versioning](https://semver.org/), with the usual pre-1.0 reading:

- **0.x minor releases may break the API.** While the version starts with `0.`, a minor bump (`0.1` to `0.2`) may contain breaking changes, and patch releases are fixes only.
- **Breaking changes come with a migration.** Every release is described by a [changeset](https://github.com/changesets/changesets), and a breaking one shows a before/after snippet. Removed names are not left behind as deprecated aliases: the 0.x line prefers a small, consistent surface to a long tail of old spellings.
- **The packages version together.** Core, the feature packages and the bindings are released as one set; a binding generated from one core version is tested against that version.

Release notes are on the [changelog](/project/changelog/) page.

## Stable vs unstable surface

| Entry point | What is public |
|---|---|
| `@sophistry/core` | Scene authoring: `createScene`, the definitions (`circle`, `axes`, `text`, ...), groups, tracks (`track`, `derive`, `watch`), clocks, animations and timelines, springs, instancing and path batches, interaction, cameras, export, and the custom-definition API (`defineShape`, `defineComposite`, ...). Covered by the versioning policy. |
| `@sophistry/core/geometry`, `/color`, `/themes` | Pure helpers: path, shape, transform, scale and morph maths; colour conversion and colormaps; themes and palettes. Public. |
| `@sophistry/text` | `mathTex`, `mathTransform`, `createLatex`, fonts and outline measurement. Public. |
| `@sophistry/charts`, `/charts/3d` | Chart definitions, channels, transforms, `chartHandle` and the pure chart maths; 3D charts on the subpath. Public. |
| `@sophistry/3d` | `camera3D`, 3D primitives and plots, projection helpers, `orbitControls3D`. Public. |
| `@sophistry/solidjs`, `@sophistry/react` (and their `/text`, `/charts`, `/charts/3d`, `/3d` subpaths) | `<Stage>`, `<MultiStage>`, `<Camera>`, the hooks, `wrap`, and one generated component per public definition. Public. A component's props are its definition's props, so they change exactly when the definition does. |
| `<package>/definitions` | The record of a package's definitions that binding codegen reads. Public for tooling; not meant for scenes. |
| `@sophistry/core/internal` | **Unstable.** Renderer, paint, bake, registry and scene plumbing for extension packages and custom renderers. It can change in any release, including patches, and is not covered by semver. |

Everything a scene author needs, including the [custom-definition API](/guides/extending/), is on the public entry points. If you find yourself importing from `/internal` to build a scene, that is a gap worth [reporting](https://github.com/BenjaminLucier/sophistry/issues).

Anything not exported from an entry point (a file path inside `src/`) is private, whatever its name suggests.

## Solid 2 release-candidate policy

The core, text, charts and 3D packages depend on no UI framework. The **Solid binding** is built on **Solid 2.0, which is currently a release candidate**; `solid-js` and `@solidjs/web` are its peer dependencies, and the repository pins the exact versions it is developed and tested against (see [Installation](/start/installation/)).

- **Pin Solid exactly.** A plain `^2.0.0` range does not match release candidates, so your package manager may otherwise resolve Solid 1.
- **Upgrades are deliberate.** When Solid publishes a new candidate, the binding moves to it in one change, runs its tests and the docs' end-to-end tests against it, and says so in the release notes.
- **Solid's changes stay in the binding.** Because the scene graph lives in the core, a change in how Solid schedules effects can only affect `@sophistry/solidjs`, never a scene built with `createScene` or the React binding.

The React binding targets React 19 through `react-reconciler`.

## Supported environments

- **Browsers:** any evergreen browser with Canvas2D. The packages are compiled to ES2023 and leave dependencies external, so your bundler decides the final target.
- **Without a framework:** `createScene({ host })` in any page; `createScene({ headless: true })` in tests and Node, where nothing touches the DOM.
- **Solid 2 start mode:** `@solidjs/vite-plugin`'s start mode works in client mode and SSR mode. A server-rendered `<Stage>` emits its host and an empty canvas, hydrates, and paints after mount.
- **Astro:** as a `client:only` island via a Solid 2 integration (the official `@astrojs/solid-js` targets Solid 1; see [Embedding](/recipes/embedding/#astro-islands)), or as a plain script calling `createScene`.
