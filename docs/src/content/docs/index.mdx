## Show me the code

A scene is a tree of nodes. In Solid it is an ordinary component; tracks are
the source of truth and bind straight into the scene graph, a Canvas2D
renderer paints it, and a `timeline` gives you a controller you can play,
pause and `seek`. The same scene can be built [without a
framework](/start/first-scene/#the-same-scene-without-a-framework) or [in
React](/start/first-scene/#the-same-scene-in-react).

## One core, any framework

The core, `@sophistry/core`, is plain TypeScript with no UI framework
dependency: a retained scene graph that recomputes only what a write
touches, instancing for thousands of items in one node, and a renderer
behind a clean spec boundary. The Solid and React bindings are generated
from the core's definitions, so every shape, chart and composite is a
component in both. See [Core concepts](/start/concepts/).

The library is pre-1.0, and the Solid binding targets **Solid 2.0**, which is
currently a release candidate, so the API may still change. What that means
in practice, and what we promise between releases, is in
[Stability and versioning](/project/stability/).

## Packages

`@sophistry/core` plus a binding (`@sophistry/solidjs` or
`@sophistry/react`), or the core alone. LaTeX, charts and 3D are separate
packages (`@sophistry/text`, `@sophistry/charts`,
`@sophistry/3d`), so you only bundle what you import. See
[Installation](/start/installation/).
