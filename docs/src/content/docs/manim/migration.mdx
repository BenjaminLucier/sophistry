sophistry borrows Manim's vocabulary, and many names carry over unchanged (`Circle`, `Axes`, `NumberPlane`, `Arrow`, `write`, `MathTex`). The model is close to Manim's too: a scene holds retained objects (nodes, Manim's mobjects) that you create, keep and change. The differences are in how they change over time: animations drive *tracks*, not objects, and a node bound to a track follows it. This page maps what you know onto what you write here.

## The mental shift

**A scene is a component or a `createScene` call, not a `construct()` method.** With the Solid binding, the Manim script becomes a component: JSX inside `<Stage>` says what is on screen, and a script started from `onSettled` says what happens over time. Without a framework, `createScene({ host })` returns the scene and `scene.add(...)` / `scene.play(...)` read almost like `self.add` / `self.play`.

**Mobjects become nodes made from definitions.** `circle.create({ radius: 1 })` in the core, or `<Circle radius={1} />` in a binding, makes a scene node. The node is the handle: keep it (`ref={(node) => ...}` in JSX) to measure it (`node.bounds()`, `node.center()`) or change it (`node.set("fill", RED)`).

**Animations take tracks, not shapes.** `track(0)` is a value that animations write; pass the track itself as a prop (`<Circle radius={radius} />`) and the node follows it. To move a circle, animate the track bound to its `center`. There is no `.animate` proxy.

**Updaters are `derive` and `watch`.** `always_redraw(lambda: ...)` and `add_updater` recompute a mobject from other values. Here `derive(x, (x) => ...)` is a computed value you pass as a prop; it recomputes only when `x` changes, once per frame at most. `watch(x, run)` runs a side effect, and `follow(target, source, spring)` chases a moving value with a spring.

**Scenes are live.** Manim renders a file. sophistry paints into a page, in real time, and every value is also available to the user: draggable points, scrubbable timelines, parameters bound to sliders.

<Aside type="tip">
When porting, start from the end state. Write the scene that draws the final frame, replace the numbers that change with `track(...)`, then add the animation script.
</Aside>

    ```tsx
    import { draw, fadeOut, morph, sequence, track } from "@sophistry/core";
    import { circlePolyline, rectPolyline } from "@sophistry/core/geometry";
    import { Polygon, Stage, usePlayer } from "@sophistry/solidjs";
    import { onSettled } from "solid-js";

    const SQUARE = rectPolyline(-1.5, -1.5, 3, 3);
    const CIRCLE = circlePolyline(0, 0, 1.5);

    function Shape() {
      const player = usePlayer();
      const points = track(SQUARE);
      const drawn = track(0);
      const opacity = track(1);

      onSettled(() => {
        void player.play(
          sequence(
            draw(drawn),
            morph(points, CIRCLE, { closed: true }),
            fadeOut(opacity),
          ),
        );
      });

      return <Polygon points={points} progress={drawn} opacity={opacity} />;
    }

    export function SquareToCircle() {
      return (
        <Stage units={8}>
          <Shape />
        </Stage>
      );
    }
    ```
  </TabItem>
  <TabItem label="sophistry (TypeScript)">
    ```ts
    import {
      createScene,
      draw,
      fadeOut,
      morph,
      polygon,
      sequence,
      track,
    } from "@sophistry/core";
    import { circlePolyline, rectPolyline } from "@sophistry/core/geometry";

    const scene = createScene({ host: document.body, units: 8 });
    const points = track(rectPolyline(-1.5, -1.5, 3, 3));
    const drawn = track(0);
    const opacity = track(1);

    scene.add(polygon.create({ points, progress: drawn, opacity }));
    ```

The polygon is bound to three tracks, and `morph` walks the `points` track from the square's outline to the circle's. `usePlayer` runs the script on the stage's clock and stops it when the component unmounts; `scene.timeline(...)` instead of `play` gives a scrubbable version of the same three animations.

## A tracker and a dot, side by side

`ValueTracker` plus `always_redraw` is the bread and butter of Manim explainers. Here it is as a track and a `derive`.

<Tabs syncKey="lang">
  <TabItem label="Manim (Python)">
    ```python
    class DotOnSine(Scene):
        def construct(self):
            axes = Axes(x_range=[0, 7, 1], y_range=[-1.5, 1.5, 0.5])
            graph = axes.plot(np.sin)
            x = ValueTracker(0)
            dot = always_redraw(
                lambda: Dot(axes.c2p(x.get_value(), np.sin(x.get_value())))
            )

            self.play(Create(axes), Create(graph))
            self.add(dot)
            self.play(x.animate.set_value(2 * PI), run_time=4)
    ```
  </TabItem>
  <TabItem label="sophistry (Solid)">
    ```tsx
    import {
      coordsOf,
      derive,
      draw,
      type SceneNode,
      sequence,
      track,
      valueTo,
    } from "@sophistry/core";
    import { Axes, Dot, FunctionGraph, Stage, usePlayer } from "@sophistry/solidjs";
    import { onSettled } from "solid-js";

    function Graph() {
      const player = usePlayer();
      const drawn = track(0);
      const x = track(0);
      let axes: SceneNode | undefined;
      // Computed at commit time, when the axes node exists.
      const at = derive(x, (x) =>
        (axes && coordsOf(axes)?.coordsToPoint(x, Math.sin(x))) ?? { x: 0, y: 0 },
      );

      onSettled(() => {
        void player.play(
          sequence(draw(drawn), valueTo(x, 2 * Math.PI, { duration: 4 })),
        );
      });

      return (
        <>
          <Axes
            ref={(node) => (axes = node)}
            xRange={[0, 7, 1]}
            yRange={[-1.5, 1.5, 0.5]}
            width={11}
            height={4.5}
          >
            <FunctionGraph function={Math.sin} progress={drawn} />
          </Axes>
          <Dot center={at} />
        </>
      );
    }

    export function DotOnSine() {
      return (
        <Stage units={14}>
          <Graph />
        </Stage>
      );
    }
    ```
  </TabItem>
</Tabs>

## Staggered reveals

<Tabs syncKey="lang">
  <TabItem label="Manim (Python)">
    ```python
    class Stagger(Scene):
        def construct(self):
            dots = VGroup(*[Dot() for _ in range(7)]).arrange(RIGHT)
            self.play(
                LaggedStart(*[FadeIn(d, shift=UP) for d in dots], lag_ratio=0.2)
            )
            self.wait(1)
    ```
  </TabItem>
  <TabItem label="sophistry (Solid)">
    ```tsx
    import {
      fadeInFrom,
      hold,
      lagged,
      sequence,
      track,
      trackPoint,
      UP,
    } from "@sophistry/core";
    import { Dot, Stage, usePlayer } from "@sophistry/solidjs";
    import { onSettled } from "solid-js";

    const XS = [-3, -2, -1, 0, 1, 2, 3];

    function Dots() {
      const player = usePlayer();
      const opacity = XS.map(() => track(0));
      const center = XS.map((x) => trackPoint(x, 0));

      onSettled(() => {
        void player.play(
          sequence(
            lagged(
              XS.map((_, index) => fadeInFrom(opacity[index], center[index], UP)),
              { lagRatio: 0.2 },
            ),
            hold(1),
          ),
        );
      });

      return XS.map((_, index) => (
        <Dot center={center[index]} opacity={opacity[index]} />
      ));
    }

    export function Stagger() {
      return (
        <Stage units={10}>
          <Dots />
        </Stage>
      );
    }
    ```
  </TabItem>
</Tabs>

Positions use `trackPoint` because `fadeInFrom` animates a position as well as an opacity. `.arrange(RIGHT)` is replaced by choosing the x values, or by `arrange(...)` over measured bounds when sizes vary. For many identical items that need no individuality, `instances(dot, { data, channels, transition: { stagger } })` does the same as one node. See [Layout](/guides/layout/).

And consecutive `await player.play(a); await player.play(b);` calls are not frame-exact; wrap them in `sequence(a, b)` inside a single `play` when timing matters. See [Animation](/guides/animation/).

### Naming

A few verbs are deliberately not Manim's, so they read as plain English where they are imported and do not collide with common words:

- `Create` / `Uncreate` are `draw` / `erase` (`write`, `unwrite` and `drawBorderThenFill` keep their names).
- `AnimationGroup` is `parallel`, the partner of `sequence`. `<Group>` is the transform container (`VGroup`), nothing else.
- `Wait` inside a composite is `hold`. `pause` would clash with `Clock.pause()` and `Timeline.pause()`, which stop playback; `hold` only occupies time. `await player.play(hold(seconds))` is the awaitable form.
- `mob.shift(v)` as an animation is `moveBy`, the relative partner of `moveTo` (and `rotateBy` of `rotateTo`). `shiftBy` in the layout helpers is unrelated.
- The matching function is `morphShapes` (in `@sophistry/core/geometry` and `@sophistry/text`); the `<TransformMatchingShapes>` component keeps Manim's name.
- Manim's `axes.plot` shape is `<FunctionGraph>`, because `Graph` in Manim is a network (`<NetworkGraph>`).
- Composite geometry takes `center` (the middle of the plotting area, graph layout, bar chart or 3D dot), `Angle` and `Elbow` take `vertex`; round shapes take `center` and `radius` too, and moving a whole shape is `x`/`y` or `place`.
- Named colours (`BLUE`, `GREY_A`, ...) are plain CSS hex strings, so they drop straight into `stroke`, `fill` and `style`.

### Rate functions

Pass an `easing` by name or as a function. The names in `easings` include `linear`, `smooth`, `in`, `out`, `inOut`, `quadInOut`, `sinIn`/`sinOut`/`sinInOut`, `expIn`/`expOut`/`expInOut`, `circInOut`, `backIn`/`backOut`/`backInOut`, `elasticOut`, `bounceOut`, `thereAndBack`, and Manim's `rushInto`, `rushFrom`, `slowInto`, `doubleSmooth`, `lingering`, `runningStart` and `exponentialDecay`. The ones that take parameters are functions returning a curve: `squish(curve, a, b)`, `runningStart(pull)`, `notQuiteThere(curve, proportion)`, `exponentialDecay(timeConstant)` (Manim's `half_life`) and `thereAndBackWithPause(hold)`. Anything else is a function value, since there is no easing registry:

```ts
import { circle, createScene, fadeIn, track } from "@sophistry/core";

const scene = createScene({ host: document.body });
const opacity = track(0);
scene.add(circle.create({ radius: 1, opacity }));
void scene.play(fadeIn(opacity, { easing: (t) => t * t * (3 - 2 * t) }));
```

## Cameras

Manim moves a camera frame object. Here the "camera" is the stage's own view, whose props are tracks like any other.

| Manim | sophistry |
|---|---|
| `config.frame_width` | `<Stage units>` |
| `self.camera.frame.animate.scale(0.5)` | `valueTo(units, ...)`, with `units` a `track` passed to the stage |
| `self.camera.frame.animate.move_to(p)` | `moveTo(center, p)`, with `center` a `trackPoint` passed to the stage |
| `MultiCamera` | `<MultiStage>` with one `<Camera>` per view |
| `SplitScreenCamera` | `<SplitScreen panes={[...]} split ratio />` |
| `setupPictureInPicture` | `<PictureInPicture main inset corner size />` |
| `setupQuadView` | `<QuadView panes={[...]} />` |
| `MovingCameraScene` | `<PanZoom>` (core: `panZoom(scene)`) for user navigation, or animate `units` and `center` |

See [Cameras](/guides/cameras/).

## What does not map

- **Video output.** There is no video encoder, no `--save_sections`, no `manim-slides`. sophistry plays live in a page; [Export stills](/recipes/export-stills/) covers PNGs and fixed-fps frame sequences.
- **Copying mobjects.** `copy`, `become`, `save_state`/`Restore`, `generate_target`/`MoveToTarget` have no equivalent; keep the state in tracks and `set` them back, or create a second node from the same props.
- **The `.animate` proxy.** Deliberately omitted. Call a preset on the track you want to change.
- **Submobject operations.** Containers have `add`, `remove` and `setChildren`, but there is no `submobjects` indexing or family flattening; keep the nodes you need in variables or arrays. In JSX, render shapes conditionally with `<Show>` and lists with `<For>`.
- **Missing shapes and animations.** `Table`/`Matrix`, `Code`, `MarkupText`, `ImageMobject`, and boolean ops are not offered yet.

The public view of what is planned is the [roadmap](/project/roadmap/).
