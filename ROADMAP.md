# Roadmap

Where sophistry is, and where it is going. This is a plain-language summary;
open work is tracked in the repository's issues. Priorities shift
with what people actually build, so treat the order within a section as a
guide, not a promise.

sophistry is pre-1.0. The core is framework-free TypeScript;
the Solid binding is built on the **Solid 2.0 release candidate** and the React
binding on React 19. See the
[stability policy](https://sophistry.dev/project/stability/).

## Shipped

- **A framework-free core.** A retained scene graph in plain TypeScript
  (`createScene`, definitions such as `circle` and `axes`), tracks with
  push-stale, pull-value updates (`track`, `derive`, `watch`), per-node stages
  and dirty bits, and one shared frame loop. No virtual DOM.
- **Generated bindings.** `@sophistry/solidjs` and `@sophistry/react`
  wrap every definition as a component (`<Circle>`), plus `<Stage>`,
  `<MultiStage>`, `<Camera>` and hooks, generated by codegen so they never fall
  behind the core.
- **Scenes and layout.** A Canvas2D stage, shapes, nodes with lazy bounds,
  relative placement (`nextTo`, `alignTo`, `toEdge`, `arrange`), groups,
  cameras, split screens and picture-in-picture.
- **Animation.** Seekable animation descriptions, a runner that owns time,
  `play()` and `timeline().seek(t)`, composites (`sequence`, `parallel`, `lagged`,
  `repeat`), creation/emphasis/indication/transform presets, morphing, and
  easings including Manim's rate functions (`squish`, `runningStart`, …).
  Movement effects (`homotopy`, `phaseFlow`, `tracedPath`), `changeSpeed`,
  and arc trajectories (`pathArc`). Seekable springs (`springTo`) and live
  spring followers (`follow`).
- **Instancing.** `instances()`: one node for many items of one shape, with
  per-item channels, keyed enter/update/exit, per-item tweens and springs, and
  picking by item; path batches for many distinct outlines.
- **Items with identity.** `createSlots` models which key sits in which slot,
  with seekable `swap`/`move`/`permute`/`rotate`/`insert`/`remove` operations
  and caller-supplied motion (eased straight moves, `arcMotion`).
- **Graphing.** `Axes`, `NumberLine`, `NumberPlane`, `PolarPlane`,
  `ComplexPlane`, log scales, `FunctionGraph`, `ParametricGraph`, `PolarGraph`,
  `ImplicitFunction`, Riemann sums, tangents
  and secants, vector fields and streamlines, network graphs with layouts.
- **Charts.** Bar, line, scatter, histogram, box, violin, radar, pie, heatmap,
  contour, hierarchy charts and more, all driven by `data` plus channel props
  and batched by default, in a `<Chart>` frame with linear, log, sqrt, symlog,
  time and band axes,
  dates and time zones, legends, tooltips, reveals, keyed transitions, facets
  and linked views.
- **Text and maths.** Rich `Text` (spans, wrapping), `BulletedList`, `Title`,
  `DecimalNumber`/`Variable` with tabular digits, LaTeX as geometry
  (`MathTex`, `MathTransform`) via KaTeX and opentype.js, and `Brace` labels.
- **3D.** `Camera3D`, primitives, polyhedra, surfaces and 3D charts
  (`Scatter3D`, `BarChart3D`, …), orbit controls, and a painter's depth sort
  across every solid under one camera, projected into the same 2D pipeline.
- **Interaction.** Draggable handles, constraints, hit testing, keyboard access.
- **Theming.** Catppuccin light/dark themes, color modes, a categorical
  `series` palette, colormaps and ramps.
- **Stills and frames.** `captureFrame`, `exportFrames`, and a deterministic
  fixed-fps `renderFrames` path as a building block for tooling.
- **Packaging.** Separate packages for the core, text, charts, 3D and each
  binding, with narrow subpaths; typed, ESM only, tree-shakeable.

## Next

### Near term: polish for a trustworthy 0.x

- Extend the algorithm-visualizer recipe (sorting and graph traversal ship)
  to heaps and tree traversals, as the forcing function for the items below.
- More gallery examples and guides.

### Medium term: expressiveness

- **Text**: `MarkupText` and syntax-highlighted `Code`.
- **Missing primitives**: `Table`/`Matrix`, `ImageMobject`, SVG import,
  boolean shape operations.
- **Animation**: common Manim migration targets still missing (`spiralIn`,
  `showIncreasingSubsets`, `ReplacementTransform`, `FadeTransform`), and
  `pathArc` on `MathTransform` and `TransformMatchingShapes`.
- **Layout through scaled or rotated groups**: make deltas exact, not
  approximate.

### Longer term: rendering and platform

- Exact 3D occlusion (splitting intersecting faces, or a depth buffer);
  today's painter's sort handles separate and concave solids but not faces
  that cut through each other.
- Soft (alpha) masks, images and textures, per-point stroke width.
- Bezier-native paths throughout. Shapes can already paint native curves
  (`curvePaths`), but most geometry still flattens to polylines.
- Per-item arc-length reveals in instances and path batches, so batched chart
  marks draw on the way individual shapes do.
- A WebGPU renderer behind the same spec boundary.
- A 3D data coordinate system, and a `ThreeDScene`-style convenience wrapper
  if composing `<Camera3D>` and `<Axes3D>` proves too verbose.
- Audio hooks.
- Python bindings: the `sophistry-py` directory only reserves the name today.
- More bindings, generated the same way.
- A 1.0 release once the API has settled (and Solid 2.0 is final, for the
  Solid binding).

## Deliberate non-goals

- Video or GIF encoding and a file writer. sophistry is interactive and
  declarative, not a render-to-file tool (stills and frame sequences are
  supported; encode them with your own tooling).
- A Python to TypeScript converter.
- A `.animate` proxy: drive tracks directly.
- `always_redraw` / `add_updater`: a `derive` passed as a prop, or `watch`,
  already does this.
- Slides and render-time sections: those presuppose a rendered video. Guided
  lessons built on tracks, the clock and draggable handles sit above this
  library.

## How to propose features

1. Search the [issues](https://github.com/BenjaminLucier/sophistry/issues) and
   this roadmap first.
2. For an idea or a question, start a
   [discussion](https://github.com/BenjaminLucier/sophistry/discussions).
3. For a concrete proposal, open a
   [feature request](https://github.com/BenjaminLucier/sophistry/issues/new?template=feature_request.yml).
   Describe the scene or interaction you are trying to build, how you do it
   today, and a sketch of the API you would like. If it mirrors a Manim feature,
   link it.
4. Pull requests are welcome; for anything larger than a fix, please agree the
   approach in an issue first. See [CONTRIBUTING.md](CONTRIBUTING.md).
